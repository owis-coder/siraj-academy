# تقرير تنفيذ المنصة المركزية — Siraj Academy

**التاريخ:** 2026-11-22
**الفرع:** `main`
**المستودع:** `owis-coder/siraj-academy`

## 1) قنوات التواصل المباشر التي اكتُشفت

راجع التفاصيل الكاملة في `docs/CENTRALIZED_COMMUNICATION_AUDIT.md`. أبرزها:

1. `POST /chat/rooms` كان ينشئ غرفة `DIRECT` بين أي مستخدمين — بما فيهم طالب ومدرس.
2. قبول العرض كان ينشئ غرفة `ORDER` بين الطالب والمدرس.
3. إشعار فوري للطالب بكل عرض مدرس (اسم + سعر) + بريد إلكتروني.
4. `GET /requests/:id/offers` كان يعرض للطالب كل عروض المنافسين.
5. تفاصيل الطلب كانت تكشف اسم المستخدم/هوية الطالب للمدرس.
6. `GET /offerings/:id/attendees` كان يكشف رقم واتساب الطلاب للمدرس.
7. حقول نصية حرة: وصف/عنوان الدورة، روابط الفيديو، نبذة المدرس، الإعلانات، مرفقات الطلبات، أسماء الملفات، رسائل المحادثة.
8. اختيار الطالب مدرسًا محددًا للخدمة عبر `providerId` متجاوزًا الإدارة.

## 2) القنوات التي أُغلقت أو حُوّلت إلى الإدارة

- أُغلقت كل مسارات إنشاء المحادثات المباشرة بين طالب ومدرس في الـBackend (لا يكفي إخفاء الأزرار).
- أُلغيت غرفة `ORDER` بين الطالب والمدرس تمامًا.
- أصبحت العروض، الأسعار المعتمدة، ومبررات المدرسين مرئية للإدارة فقط.
- غرف الطالب/المدرس القديمة: **قراءة فقط** مع الحفاظ على السجل (لم يُحذف شيء).
- أُزيل `whatsapp` من استجابات المدرس عن الطلاب.
- `providerId` القادم من الطالب يُتجاهل.
- قنوات الأكاديمية الرسمية (الدعم/الفوتر) بقيت كما هي لأنها مملوكة للإدارة.

## 3) كيفية فرض منع التواصل في الـBackend

| الطبقة | التنفيذ |
|--------|---------|
| API | `chat.ts` يرفض إنشاء غرفة/إرسال رسالة في أي مسار غير مُمرَّر عبر الإدارة (`403`). |
| API | `offers.ts` يعيد كتابة دورة العروض: قرار إداري فقط، ولا غرفة محادثة. |
| API | `requests.ts` يخفي هوية الطالب عن المدرس والعروض الداخلية عن الطالب. |
| API | `offerings.ts` يمنع المدرس من `PUBLISHED`، ويعيد الدورات المعدّلة للمراجعة. |
| التحقق | Zod على كل الحقول، و`requireApprovedTeacher`، وفحص YouTube فقط. |
| قاعدة البيانات | `ReviewStatus` + `approvedYoutubeUrls` + `trialVideoStatus` + `Lesson.reviewStatus` + حالة العرض `APPROVED/NEEDS_REVISION` + `ContentModerationLog`. |
| الفحص المركزي | `apps/server/src/lib/contentModeration.ts` + `moderationLog.ts` على كل مدخل نصي. |

## 4) دورة طلبات الخدمات والعروض

```
الطالب: طلب (PENDING_REVIEW) ──الإدارة تنشر──▶ OPEN
المدرس: عرض (PENDING) ──▶ الإدارة تقارن وتختار
الإدارة: approve ──▶ عرض واحد APPROVED + بقية العروض REJECTED + الطلب TEACHER_SELECTED
الطالب: confirm ──▶ Order(AWAITING_PAYMENT) بدون أي غرفة بين الطالب والمدرس
```

- «لماذا ترى أنك الأنسب لتنفيذ هذه الخدمة؟» أصبحت صياغة حقل المبرر في واجهتي المدرس والطلب.
- الإدارة تحدد السعر النهائي (`approvedPrice`) قبل وصول العرض للطالب.
- لا تُنشأ محادثة تلقائية بعد اختيار المدرس؛ التنسيق عبر الإدارة.

## 5) آلية اعتماد الدورات والفيديوهات

- دورة الحياة: `DRAFT → PENDING_REVIEW → NEEDS_REVISION | REJECTED | PUBLISHED` مع إمكانية `HIDDEN`.
- النشر حصري للإدارة؛ `/submit` لا يتجاوز `PENDING_REVIEW`.
- اعتماد النشر يعتمد روابط الفيديو والوسائط المعلّقة.
- مسارات مستقلة: `PATCH /admin/offerings/:id/media` و`PATCH /admin/lessons/:id/media`.
- الاستجابة العامة لا تُرسل أي رابط فيديو غير معتمد.
- عدم محاولة تجاوز قيود تضمين YouTube: الروابط تُخزَّن كما هي؛ إذا منع المالك التضمين تظهر حالته في المشغّل، ولا يوجد أي كسر لقيود الفيديو.

## 6) سبب مشكلة عدم ظهور الدورات

التفاصيل في `docs/COURSE_PUBLICATION_BUG_AUDIT.md`. الأسباب:
1. طابور المراجعة لم يكن مقروءًا في لوحة الإدارة، وفلترة `PENDING_REVIEW` غير مسموحة في مخططي التحقق.
2. طريق مسدود بعد `REJECTED`: `/submit` يرفضها ولا توجد حالة `NEEDS_REVISION`.
3. لا فصل بين اعتماد الدورة واعتماد روابط الفيديو.
4. تعديل دورة منشورة لم يكن يعيدها للمراجعة.
5. إنشاء مقرر جديد عند كل اختلاف بسيط في الاسم اليدوي.

## 7) الإصلاحات المنفَّذة

- إضافة `NEEDS_REVISION` و`ReviewStatus` وتحديث المخططات والخدمات والواجهات.
- إصلاح مخططات الفلترة والتحقق.
- إعادة كتابة دورة العروض لتصبح إدارية بالكامل.
- إعادة كتابة حماية المحادثات.
- إزالة كشف بيانات الاتصال من الاستجابات.
- حماية روابط الفيديو والوسائط بحالة اعتماد لكل عنصر.

## 8) آلية فحص المحتوى

`ContentModerationService` (نقي، بلا قاعدة بيانات) + `reviewContent` (يسجل في القاعدة):
- تطبيع Unicode/NFKC، أرقام عربية وهندية، رموز مخفية، تطويل، حروف كاملة العرض.
- كشف الهاتف (9–15 رقمًا) بصيغ متعددة: مسافات، شرطات، نقاط، أرقام عربية، وحتى أرقام مكتوبة بالكلمات.
- كشف البريد المباشر والملغّم (`[at]` / `(dot)`).
- كشف منصات التواصل (تيليجرام/واتساب/فيسبوك/إنستقرام/سناب/تيك توك/ديسكورد/تويتر) وأسماء النطاقات والمعرّفات.
- كشف عبارات تحويل التواصل بالعربية والإنجليزية.
- الروابط القصيرة → `NEEDS_REVIEW`، والخارجية → `REJECTED`، وYouTube → `NEEDS_REVIEW` دائمًا قبل النشر.
- فحص أسماء الملفات.
- النتائج: `APPROVED | NEEDS_REVIEW | REJECTED` مع رسالة سبب مفهومة (عربي/إنجليزي)، وسجل مراجعة إداري لكل محتوى غير مقبول.
- لا حذف صامت: المحتوى المرفوض يُرفض قبل الحفظ برسالة توضّح السبب وطريقة التصحيح.

## 14) حالة GitHub

- الفرع: `main`.
- Remote: GitHub (المستودع المحدد في إعدادات Git).
- ⚠️ **تنبيه أمني:** Remote URL في `.git/config` يحتوي توكن وصول شخصي مضمّنًا. لم يُطبع ولم يُدرج في أي ملف/Commit. يجب تدوير التوكن واستخدام مدير اعتماد أو SSH بدلًا من تضمينه في الرابط.
- **الـCommit:** `d01c6a4` — `feat(platform): centralize teacher-student communication and gate course publication`.
- **الـPush:** نجح إلى `origin/main` (`20f0e4f..d01c6a4`) دون Force Push، والفروع لم تُحذف، ولا يوجد تباعد بين المحلي والبعيد (`0 ahead / 0 behind`).
- ملفات `.env` و`uploads/` و`node_modules` مستثناة عبر `.gitignore`، ولم تُفحص قيم السر.

## 15) حالة النشر على Vercel

- **لم يُنفَّذ أي نشر إنتاجي.** لا يوجد في المستودع إعداد Vercel مؤكد (لا `vercel.json`)، والكود خلف الخادم Express + Postgres وليس Serverless جاهزًا.
- لم يُطبَّق أي Migration إنتاجي. ملف الـmigration الجديد موجود فقط:
  `apps/server/prisma/migrations/20261122120000_centralized_communication_and_moderation/migration.sql`
- خطة النشر الآمنة:
  1. نسخة احتياطية: `npm --prefix apps/server run backup:db`.
  2. مراجعة SQL (إضافي غير مدمّر: `ADD COLUMN`/`CREATE TABLE`/`ADD VALUE`، مع تعبئة `approvedYoutubeUrls` من `youtubeUrls` للتوافق).
  3. تطبيق على قاعدة اختبار ثم Smoke Tests.
  4. نشر الكود ثم تطبيق الـmigration على الإنتاج بموافقة صريحة.
  5. التحقق من متغيرات البيئة (لا `localhost`)، Domain/HTTPS، وسجلات النشر.
