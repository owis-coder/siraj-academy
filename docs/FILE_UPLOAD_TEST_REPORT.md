# تقرير اختبار رفع الملفات والتخزين — Siraj Academy

> التاريخ: 2026-11-22
> البيئة: Windows / Node + tsx / Vite، قاعدة بيانات **لم تُستخدم** في الاختبارات (Neon إنتاجية غير معزولة).
> القاعدة المتبعة: لا اختبار على بيانات إنتاجية، ولا Migration، ولا اتصال Google Drive حقيقي.

## ما تم تشغيله فعليًا

| الفحص | الأمر | النتيجة |
|---|---|---|
| اختبارات أمان الملفات | `cd apps/server && npx vitest run tests/file-storage-security.test.ts` | ✅ 21/21 |
| تطابق الترجمة | `npx vitest run tests/i18n-parity.test.ts` | ✅ 3/3 |
| تحقق TypeScript للخادم | `cd apps/server && npx tsc --noEmit` | ✅ بلا أخطاء |
| بناء الواجهة | `cd apps/web && npm run build` | ✅ نجح (تحذير حجم الحزمة 886KB فقط) |
| توليد Prisma Client | `npx prisma generate` | ✅ |
| صحة تنسيق Prisma | `npx prisma format` | ✅ |

### ما يغطيه اختبار الوحدة (21 حالة)

- تسمية الملفات: الصيغة، UUID فريد، تنظيف المسارات، الحروف العربية.
- بصمات المحتوى: PDF/PNG/ZIP/OLE، رفض المحتوى المتنكر، رفض التنفيذيات.
- التحقق من الرفع: امتداد مرفوض، محتوى لا يطابق النوع، حجم يتجاوز الحد.
- صلاحيات التصنيفات: الطالب لا يستخدم تصنيفات المدرس والعكس.
- أسماء مجلدات Drive: المعرّف الثابت يفرّق الأسماء المتشابهة.
- تشفير Refresh Token: تشفير/فك، فشل بمفتاح مختلف، وعدم إفشاء الأسرار في حالة الإعداد.

## ما لم يُشغَّل (وأسباب صريحة)

| الفحص | السبب | كيف يُنفَّذ لاحقًا |
|---|---|---|
| `prisma migrate deploy` / تطبيق Migration | قاعدة Neon إنتاجية، ولم تُمنح موافقة صريحة | قاعدة اختبار معزولة + نسخة احتياطية + موافقة |
| رفع حقيقي إلى Google Drive | لا توجد بيانات اعتماد OAuth | `docs/GOOGLE_OAUTH_SETUP.md` ثم `scripts/google-drive-setup.ts check` |
| اختبارات API على قاعدة بيانات | تحتاج `DATABASE_URL` لقاعدة اختبار وخادمًا محليًا | تشغيل الخادم على قاعدة الاختبار |
| اختبار واجهة تفاعلي (رفع/سحب/إلغاء) | لم يُطلب فحص بصري شامل | فحص يدوي على بيئة اختبار |
| اختبار الحمل والملفات 100MB | يحتاج بيئة اختبار وسعة Drive | توليد ملفات اختبار على قاعدة معزولة |

## مطابقة قائمة الأمان المطلوبة (22 بندًا)

| # | البند | الحالة | الدليل |

| 2 | المدرس يرفع إلى مجلده فقط | ✅ كود + اختبار | نفس المصدر |

| 5 | الطالب لا ينزّل ملفات طالب آخر | ✅ كود | لا يوجد Endpoint تنزيل للمستخدم؛ `/files/mine` بفلتر المالك |
| 6 | المدرس لا ينزّل ملفات الطلاب | ✅ كود | التنزيل `ADMIN` فقط |

| 13 | لا تجاوز حد الحجم | ✅ اختبار | `validateUploadedFile` + Multer `limits` |
| 14 | رفع أكثر من ملف | ✅ كود | `files` حتى 10 + MultiFileUploader |

| 17 | لا استبدال إثبات سابق | ✅ كود | كل تقديم `Payment` جديد؛ لا `update` للملف |
| 18 | لا تعديل دفعة معتمدة | ✅ كود | يُرفض التقديم عند `AWAITING_REVIEW`/`PAID` |
| 19 | استكمال الرفع بعد الانقطاع | ⚠️ كود فقط | Resumable + `uploadSessionUrl`، لم يُختبر حيًا |
| 20 | لا سجلات مكررة | ✅ كود + اختبار جزئي | `idempotencyKey` unique |

## ما يجب فعله قبل الإنتاج

1. إنشاء قاعدة اختبار معزولة وتطبيق `20261122150000_google_drive_storage`.
2. إعداد OAuth وتشغيل `scripts/google-drive-setup.ts check`.
3. رفع ملف تجريبي والتحقق من المجلد الصحيح وعدم المشاركة.
4. اختبار حسابين (طالب/مدرس) للتأكد من العزل.
5. اختبار تنزيل الأدمن ورفض غير الأدمن (401/403).
6. اختبار استكمال الرفع بقطع الشبكة.
7. مراجعة الحصة والنسخ الاحتياطي.

## الخلاصة

- الاختبارات القابلة للتشغيل محليًا **ناجحة بالكامل** (21/21) والبناء والتحقق النوعي ناجحان.
- التكامل مع Google Drive **غير مُتحقَّق منه حيًا** لعدم وجود بيانات اعتماد، ولا يمكن وصفه بـ«متصل».
- Migration **لم تُطبَّق** على أي قاعدة بيانات.
