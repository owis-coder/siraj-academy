# تقرير فحص قنوات التواصل المباشر — Siraj Academy

**تاريخ الفحص:** 2026-11-22
**النطاق:** كامل المستودع (`apps/server` + `apps/web` + Prisma schema + seed/docs)
**الهدف:** حصر كل مسار يسمح للطالب والمدرس بالتواصل أو بتبادل بيانات الاتصال، قبل التعديل وبعده.

---

## 1) خلاصة تنفيذية

قبل التعديل كانت المنصة تحتوي على **مسارات تواصل مباشر فعلية في الـBackend**، وليست مجرد أزرار في الواجهة:

| # | القناة | المكان قبل التعديل | الصلاحية | الخطورة | الإجراء المنفَّذ |
|---|--------|--------------------|----------|---------|------------------|
| 1 | إنشاء غرفة `DIRECT` مع أي مستخدم | `apps/server/src/routes/chat.ts` → `POST /chat/rooms` (`peerId`) | أي مستخدم مسجل | **حرجة** — طالب يفتح محادثة خاصة مع أي مدرس والعكس | حُصر الإنشاء: غير الإدارة لا ينشئ غرفة إلا مع الإدارة (الدعم). الغرف القديمة أصبحت للقراءة فقط ولا تُحذف. |
| 2 | غرفة `ORDER` بين الطالب والمدرس عند قبول العرض | `apps/server/src/routes/offers.ts` (النسخة السابقة) | طالب (قبول عرض) | **حرجة** — قناة تواصل دائمة بعد اختيار المدرس | أُزيلت بالكامل من دورة العروض. لا تُنشأ أي غرفة عند اعتماد العرض أو تأكيده. |
| 3 | إشعار فوري للطالب بكل عرض جديد باسم المدرس وسعره | `requests.ts` → `POST /requests/:id/offers` | مدرس معتمد | **عالية** — يكشف العروض المنافسة ويبدأ تفاوضًا مباشرًا | أصبح الإشعار للإدارة فقط، والمدرس يتلقى إشعار استلام فقط. |
| 4 | قراءة الطالب لجميع عروض المدرسين | `GET /requests/:id/offers` + `offers` داخل `GET /requests/:id` | صاحب الطلب | **عالية** — كشف أسعار ورسائل المنافسين | أصبحت للـADMIN فقط. الطالب يرى `publishedOffer` الواحد المعتمد. |
| 5 | كشف هوية الطالب للمدرس (الاسم/المستخدم) في تفاصيل الطلب | `requests.ts` → `GET /requests/:id` | مدرس معتمد أو صاحب عرض | **متوسطة** — تمكين التواصل خارج المنصة (اسم + بحث) | أُزيل كائن `student` للمدرس. الإدارة والمالك فقط يرونه. |
| 6 | كشف رقم واتساب الطلاب للمدرس | `offerings.ts` → `GET /offerings/:id/attendees` | مالك الدورة | **حرجة** — رقم اتصال مباشر | حُذف `whatsapp` من الاستجابة؛ بقي الاسم والجامعة فقط. |
| 7 | نص حر في عنوان/وصف الدورة بدون فلترة | `offerings.ts` إنشاء/تعديل + `CourseOffering.summary` | مدرس معتمد | **عالية** — رقم/تيليجرام/بريد داخل الوصف المنشور | فحص مركزي + منع الحفظ + سجل مراجعة. |
| 8 | روابط فيديو حرة (أي نطاق) في الدروس/الدورة | `offerings.ts` (`trialVideoUrl`, `youtubeUrls`, `Lesson.videoUrl`) | مدرس معتمد | **عالية** — تحويل الطالب لقناة خارجية | YouTube فقط + حالة `ReviewStatus` لكل رابط + `approvedYoutubeUrls`. |
| 9 | مرفقات وروابط الطلبات (`linkUrl`, `attachments`) | `requests.ts` + `customRequests.ts` | طالب | **متوسطة** — بيانات اتصال داخل المرفقات/الأسماء | فحص الحقول وأسماء الملفات؛ الروابط الخارجية مرفوضة. |
| 10 | أسماء الملفات المرفوعة | `POST /uploads` | أي مستخدم مسجل | **متوسطة** — `whatsapp-055....pdf` | فحص اسم الملف وحذف الملف المرفوض. |
| 11 | نص الرسائل داخل المحادثات | `POST /chat/rooms/:id/messages` | مشارك الغرفة | **عالية** — تبادل أرقام/روابط حتى في غرفة الدعم | فحص كل رسالة غير إدارية + منع إرسال أي بيانات اتصال. |
| 12 | نص حر في نبذة المدرس وتخصصاته | `teacher.ts` → `PATCH /teacher/profile` | مدرس | **متوسطة** — رقم داخل الملف العام | فحص `bio/specialties/universitiesText/degree`. |
| 13 | نص حر في الإعلانات وروابطها | `ads.ts` | مدرس معتمد | **متوسطة** | فحص قبل الحفظ + مراجعة إدارية كما كان. |
| 14 | اختيار الطالب مدرسًا محددًا لخدمة مباشرة | `catalog.ts` → `POST /service-orders` (`providerId`) | طالب | **متوسطة** — تجاوز الإدارة في التعيين | يُتجاهل `providerId` القادم من العميل؛ يُعتمد تعيين الإدارة فقط. |
| 15 | بريد إشعار الطلب المخصص يحتوي بيانات الطالب | `customRequests.ts` → `sendAdminNotificationEmail` | إدارة فقط | منخفضة — مقصودة | بقي كما هو؛ الإدارة هي المستقبِل. |

قنوات تبقى **مقصودة ومشروعة**:
- محادثة الطالب ↔ الإدارة (الدعم الفني) ومحادثة المدرس ↔ الإدارة.
- أرقام/روابط الأكاديمية الرسمية في `Footer` و`Payment` (يديرها الأدمن من الإعدادات وليست تابعة لمدرس).
- واتساب الطالب يظهر **للإدارة فقط** في لوحات الإدارة (ضروري للتواصل الرسمي).

## 2) مسارات API بعد التعديل

### المحادثات (`/api/v1/chat`)
- `POST /rooms`:
  - غير الأدمن: مسموح فقط إذا كان الطرف الآخر `ADMIN` (الدعم). وإلا `403` برسالة أن الإدارة هي الوسيط.
  - إنشاء المجموعات: `ADMIN` فقط.
- `POST /rooms/:id/messages`:
  - أي رسالة من غير الأدمن تُفحص بـ`ContentModerationService`. أي نتيجة غير `APPROVED` → `400` + تسجيل في `ContentModerationLog`.
  - غرفة تضم طالبًا ومدرسًا بلا إدارة (تراثية): **قراءة فقط**، لا يمكن الإرسال. السجل محفوظ ولا يُحذف.
  - المرفقات: `/uploads/...` فقط.
- `GET /rooms`: كل غرفة تُرجع `mediated` و`readOnly`؛ الواجهة تُظهر حالة القراءة فقط.

### العروض (`/api/v1/offers`)
| المسار | الصلاحية | السلوك |
|--------|----------|--------|
| `POST /:id/approve` | ADMIN | يعتمد عرضًا واحدًا (`APPROVED`)، يرفض البقية، يحوّل الطلب `TEACHER_SELECTED`، ويُرسل للطالب العرض المعتمد فقط. |
| `POST /:id/request-changes` | ADMIN | `NEEDS_REVISION` + ملاحظة للمدرس. |
| `POST /:id/reject` | ADMIN | رفض مع ملاحظة. |
| `POST /:id/confirm` | STUDENT (صاحب الطلب) | يقبل العرض **المعتمد فقط** ويُنشئ طلب دفع. لا غرفة محادثة. |
| `GET /` | ADMIN | كل العروض الداخلية للمقارنة. |
| `GET /:id` | ADMIN أو صاحب العرض | لا وصول لمنافس. |
| `POST /:id/withdraw` | صاحب العرض | قبل قرار الإدارة فقط. |
| `POST /:id/accept` | ADMIN | `410 Gone` — توضيح أن القرار إداري (لمنع أي عميل قديم). |

### الطلبات (`/api/v1/requests`)
- الإنشاء: فحص `courseTitle/details/deadline/linkUrl/attachments` قبل الحفظ.
- `GET /:id/offers`: `ADMIN` فقط.
- `GET /:id`: المدرس لا يستلم `student`؛ الطالب يستلم `publishedOffer` فقط (بلا رسائل المنافسين أو ملاحظات الإدارة).
- `POST /:id/offers`: يفحص مبرر المدرس ويُشعر الإدارة فقط.

### الدورات (`/api/v1/offerings`)
- لا يمكن للمدرس الوصول إلى `PUBLISHED` بأي مسار: `PATCH` يرفض `status=PUBLISHED` لغير الأدمن، و`/submit` ينقل إلى `PENDING_REVIEW` فقط.
- أي تعديل جوهري على دورة منشورة (عنوان/وصف/سعر/فيديو/مقرر) يعيدها `PENDING_REVIEW`.
- أي درس جديد أو تعديل على عنوان/رابط درس: `reviewStatus = PENDING_REVIEW`، وإذا كانت الدورة منشورة تعود للمراجعة.
- استجابة الدورة العامة لا تتضمن:
  - روابط YouTube غير المعتمدة (`approvedYoutubeUrls` فقط).
  - `trialVideoUrl` قبل `trialVideoStatus=APPROVED`.
  - `videoUrl` لأي درس `reviewStatus != APPROVED`.
  - `adminNote`.

## 3) المخاطر المتبقية والحدود

1. **محتوى تاريخي**: الرسائل والدورات والملفات القديمة لم تُحذف ولم تُعدّل جماعيًا (وفق شرط عدم الحذف). أي محتوى منشور سابقًا قد يحتوي بيانات اتصال؛ يُعالج عند أول تعديل (يعود للمراجعة)، ويمكن للإدارة إخفاؤه يدويًا.
2. **الفلترة ليست حماية كاملة**: النصوص المموّهة بشدة (صور داخل PDF، رموز صوتية) تتجاوز النص. لذلك كل محتوى `NEEDS_REVIEW` لا يُنشر قبل اعتماد الإدارة، والمحتوى المرفوض يُسجَّل.
3. **`NEEDS_REVIEW` في المحادثات**: يُرفض الإرسال بدلًا من تخزينه للمراجعة، لأن المحادثة قناة مباشرة.
4. **بريد الإدارة**: بريد الطلب المخصص يحتوي بيانات الطالب — مقصود، والمستقبِل هو الإدارة فقط.
