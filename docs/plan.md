# خطة تنفيذ أكاديمية سراج

## البنية التقنية
```
موقع سراج/
├─ apps/server/        Node + Express + TS + Prisma + PostgreSQL + Socket.IO + Zod
├─ apps/web/           React + Vite + TS + Tailwind (RTL, ألوان سراج)
├─ docs/               التحليل والهوية وعقد API (مرجع فريق البناء)
├─ assets/brand/        أصول الشعار (ملكية العميل)
└─ docker-compose.yml  postgres للتشغيل المحلي
```

## المراحل — حالة التنفيذ
| المرحلة | النطاق | المالك |
|---|---|---|
| 1. تحليل قمة + الهوية | تحليل موثّق في docs | ✅ منجزة |
| 2. البنية + dotenv + JWT + RBAC + Prisma schema + auth | backend-agent + مراجعة | قيد التنفيذ |
| 3. الجامعات/الكليات/التخصصات/المقررات + التصفّح التسلسلي | backend + web | قيد التنفيذ |
| 4. حسابات الطالب/المدرس + لوحات | backend + web | قيد التنفيذ |
| 5. الدورات + الخدمات + طلبات الشرح + العروض | backend + web | قيد التنفيذ |
| 6. الدفع اليدوي (سند + مراجعة) + تلغرام + إشعارات | backend + web | قيد التنفيذ |
| 7. محادثات + إشعارات + موافقات إعلانات/منشورات | backend + web | قيد التنفيذ (socket أساسي) |
| 8. لوحة الإدارة + إحصائيات حقيقية | web | قيد التنفيذ |
| 9. اختبارات + أمان تحسين + نشر | مرحلة لاحقة | بعد المراجعة الأولى |

## فكّرت مهمة مُطبّقة
- كل بيانات (شركات الجامعات إلى العروض) في قاعدة بيانات، لا شيء مكتوب في الواجهة، أو إدخالات ببيانات وهمية.
- ليس هناك أرقام منفصلة (عدد الطلاب/المدرسين) — تُعرض فقط ما يعود للجدول واحدڭ.
- حساب المدرس تحقق: الإدارة → APPROVED.
- إعلان بالمدرس: DRAFT → PENDING_REVIEW → APPROVED (تعديل جوهري يعيده إلى المراجعة عبر الخادم).
- الدفع: التحويل يدوي — يعامل "اصطفاع السند" باعتبارس وثيقة انتظار، لا نجاح تلقائي.
- السقوط: المبلغ/IBAN/تلغرام من الإعدادات (لو الإدارة).
- النزاهة الأكاديمية: نص الخدمات قابل للتعديل من الإدارة، والأكاديمية المبدئية صياغة **تدريب/شرح** (لا تسليم أعمال من وصلة).
